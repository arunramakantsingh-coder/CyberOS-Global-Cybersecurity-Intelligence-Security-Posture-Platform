# CyberOS M2.1 — Tenant-Relevant Threat Intelligence

## Objective

Turn CyberOS Threat Intelligence from a global intelligence viewer into a tenant-aware intelligence service.

The governing question is:

> Does this global threat matter to this organization, its assets, technology, exposure, vulnerabilities, geography and sector?

## Security boundary

CyberOS maintains two distinct data planes:

1. **Global intelligence** — reusable threat knowledge such as actors, campaigns, malware, IOCs, CVEs, TTPs, geopolitical signals and sector targeting.
2. **Tenant intelligence** — correlations derived from a specific customer's tenant profile, assets, findings, exposure, controls and telemetry.

Global intelligence may be shared. Tenant-derived intelligence must remain tenant-scoped.

## Correlation flow

```text
Global Intelligence
      |
      v
Normalization / enrichment
      |
      v
Tenant context
  - sector
  - geography
  - technology
  - assets
  - exposure
  - vulnerabilities
  - identity / controls
      |
      v
Correlation rules
      |
      v
Relevance scoring
      |
      +---- affected assets
      +---- related findings
      +---- ATT&CK TTPs
      +---- CVEs
      +---- confidence
      +---- evidence / reasons
      |
      v
Command Center + Threat Intelligence + downstream modules
```

## Current implementation

M2.1 introduces a safe, synthetic correlation service without changing the frozen public website layout or existing tenant schema.

### API

- `GET /api/v1/threat-intelligence/global`
- `GET /api/v1/threat-intelligence/profile`
- `GET /api/v1/threat-intelligence/correlations`

The service reads only the current `cyberos-demo` tenant and its tenant-scoped assets/findings.

## Correlation dimensions

The first implementation evaluates:

- tenant sector
- tenant geography
- technology footprint
- internet-facing exposure
- related finding/CVE text
- campaign-relevant finding signals
- affected tenant assets

The resulting score is bounded to 0–100 and translated to `critical`, `high`, `medium` or `monitor` priority.

## Future intelligence sources

The normalized model is intentionally compatible with STIX-style intelligence objects and ATT&CK relationships. MITRE ATT&CK publishes machine-readable STIX content and provides TAXII access, making STIX/TAXII a suitable future ingestion boundary. See the official ATT&CK data and TAXII guidance for integration planning.

## Downstream propagation

Tenant correlations will become the shared intelligence context for:

- Command Center
- Vulnerability Management
- Attack Surface
- Security Posture
- Web & API Security
- Network & Hardening
- Compliance/GRC
- Cyber AI
- Reports

## Non-goals for M2.1

- No live external threat-feed ingestion yet.
- No autonomous offensive execution.
- No cross-tenant telemetry sharing.
- No arbitrary customer-network scanning.
- No modification of the frozen public website visual system.

## Acceptance criteria

- Global intelligence and tenant-derived intelligence are visibly separated.
- Correlation results include tenant ID, relevance score, confidence, reasons and matched assets.
- Tenant queries always include tenant scoping.
- A global intelligence object with no tenant match is shown as `monitor`, not silently treated as a tenant finding.
- Existing M2 public website remains unchanged.
- API health and existing M2 routes remain operational.
